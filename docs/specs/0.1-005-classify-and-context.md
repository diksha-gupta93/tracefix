# Task 0.1.5 — Classify Failure and Select Relevant Context

## 1. Goal

Implement deterministic failure classification and bounded, model-safe context selection for a successfully reproduced v0.1 baseline failure. Convert existing typed baseline evidence into the existing runtime `FailureAnalysis` contract and a new fully typed context package containing only the evidence and repository material needed by the later repair-planning task.

This task ends after producing and validating those typed values. It does not call a model, plan a repair, generate or apply a patch, or construct the LangGraph workflow.

## 2. Context

Task 0.1.4 prepares an isolated copy of a seeded failing snapshot and returns `BaselineResult` with bounded sandbox stdout/stderr. Only `BaselineOutcome.REPRODUCED_FAILURE` is eligible for this task; non-reproducible and infrastructure outcomes are terminal and must not be reclassified.

`app.agent.schemas.FailureCategory` already defines the runtime categories required by the architecture: `syntax_failure`, `import_or_dependency_failure`, `assertion_failure`, `incorrect_exception_behaviour`, `type_related_failure`, `timeout`, `test_environment_failure`, and `unsupported_or_ambiguous`.

These runtime categories are intentionally distinct from `benchmarks.loader.BugCategory`, which describes how a seeded defect was authored and must not be used as the classification answer.

The trusted benchmark view contains evaluator-only hidden tests and reference patches. The existing model-safe view omits those artifacts but exposes the entire fixture repository. This task must select a smaller package from the prepared repository and preserve the evaluator/model trust boundary. Repository content and test output are untrusted data, not instructions to TraceFix.

## 3. In Scope

- Add a typed classifier that accepts a reproduced `BaselineResult` and produces `FailureAnalysis` using only baseline evidence and deterministic rules.
- Classify recognized pytest/Python failure evidence into the existing runtime categories. Rules must have explicit precedence and a deterministic fallback to `unsupported_or_ambiguous` when evidence is absent, conflicting, materially truncated, or not safely recognized.
- Build a typed, immutable context package from the matching trusted case, prepared repository, baseline evidence, and classification.
- Include, when available and within budget:
  - issue description;
  - failing visible test or relevant bounded excerpt;
  - bounded pytest traceback/stack trace;
  - source files referenced by safe repository-relative traceback frames;
  - relevant function, class, and type definitions found through static Python parsing;
  - directly relevant imports;
  - applicable repository instruction files;
  - protected-path policy for the future repair planner.
- Use typed context items carrying normalized `PurePosixPath`, content/excerpt, item kind, and deterministic inclusion/truncation metadata. Record size limit, actual UTF-8 byte size, and whether safe material was omitted for size.
- Select deterministically in this priority: mandatory issue/classification/policy metadata; failure trace; failing visible-test excerpt; traceback-referenced source; related definitions/imports/types; applicable repository instructions. Within a priority, order by normalized path and source position.
- Parse source only as text/AST on the host. Syntax errors must remain classifiable and must not cause repository imports, test collection, module execution, or subprocess execution.
- Reject unsafe or stale inputs and fail closed when model safety cannot be established.
- Update `LocalRepairCaseState` through a typed operation, or return typed values suitable for that update, so `failure_analysis` can be populated and status can become `analysis_complete` without dictionaries.
- Add unit tests for all new behavior. Integration-style tests may exercise all five fixture shapes with injected or temporary inputs; Docker is not required because this task consumes captured baseline evidence.

## 4. Out of Scope

- Re-running baseline tests, running hidden tests, or executing repository code.
- Changing repository preparation, sandbox execution, command validation, resource limits, fingerprints, cleanup ownership, benchmark manifests, fixture contents, or evaluator layout.
- Model adapters, prompts, tokenization libraries, calls, repair plans, patch generation/application, patch policy, static gates, candidate verification, or evaluation.
- LangGraph installation/nodes, routing, retries, CLI/API behavior, artifacts, persistence, queues, GitHub integration, or observability infrastructure.
- Using expected behavior, benchmark bug category, difficulty, risk, expected/forbidden changed files, hidden tests, or reference patches as classification evidence or repair hints.
- General semantic search, embeddings, language servers, dependency resolution, repository-wide indexing, or non-Python/non-pytest support.
- Comprehensive secret-scanning or generated-artifact products. This task adds a conservative context exclusion boundary; later patch/static hardening remains in Tasks 0.1.7, 0.1.8, and 0.2.7.
- Architecture changes unless a contradiction requires separate human approval.

## 6. Python and Packaging Requirements

- Use existing CPython `>=3.14,<3.15` and `.venv`; do not install another runtime or environment.
- Use Pydantic v2 for cross-module structures. New models are strict, extra-forbidding, and frozen unless mutation is explicitly justified.
- Fully type all interfaces. No `Any` or implicit untyped dictionaries.
- Reuse `FailureCategory`, `FailureAnalysis`, `BaselineResult`, `RepositoryPreparation`, and `LocalRepairCaseState`; do not create another runtime taxonomy.
- Use standard-library `pathlib`/`PurePosixPath`, `enum`, regex, and `ast`. Do not use `eval`, `exec`, fixture imports, shell commands, or host subprocesses.
- Add no runtime or development dependency, including tokenizer, parser, search, model SDK, LangGraph, or secret-scanning packages.
- Keep current setuptools metadata/discovery unchanged absent a separately reviewed demonstrated need.
- Measure context limits from exact downstream-visible UTF-8 bytes, not character counts or native line endings. The shared default is explicit, positive, typed, test-overridable, and enforced before return.

## 8. Cross-Platform Requirements

- Normalize repository-relative paths to `PurePosixPath`; output/order match on Windows and Linux for identical bytes/evidence.
- Accept traceback paths only after separator normalization and validation. Reject absolute, drive-relative, UNC/device, empty/dot/traversal, NUL, case-alias, and out-of-repository paths.
- Match preparation's fail-closed handling of symlinks and Windows junction/reparse aliases. Do not follow links or read special files.
- Use UTF-8 explicitly. Invalid UTF-8, unreadable files, newline differences, and AST errors have deterministic omission or typed-failure behavior and never use locale decoding.
- Do not depend on Unix modes, inode semantics, shell tools, native separators, or case-sensitive-only comparisons.
- Windows uses `.venv\Scripts\python.exe`; POSIX uses `.venv/bin/python`. The portable activated command remains `python scripts/check.py`.

## 10. Security Considerations

- Treat prepared bytes, pytest output, tracebacks, and repository instructions as untrusted data. Reading/parsing never executes code or changes policy.
- Operate only on a reproduced failure whose preparation identity matches the trusted case. Revalidate containment and preparation fingerprint before reading context.
- Never read the evaluator directory. Hidden-test/reference-patch paths and case-insensitive aliases are denied before ranking, reading, or accounting.
- Exclude unrelated files, generated/cache/build artifacts, binary/non-UTF-8 files, and credential/secret-bearing paths. Apply conservative content checks before inclusion so recognized credentials/private keys cannot enter output.
- Never include environment variables, absolute host paths, home data, `.git`, Docker data, or TraceFix secrets in context/diagnostics.
- Label repository instructions as untrusted context. They cannot override policy, exclusions, protected paths, or budget.
- Represent protected paths as immutable structured data covering the architecture defaults and dependency lock files; grant no exceptions.
- Account for every downstream-visible string. Do not split UTF-8 code points. Mandatory metadata overflow is a typed failure, not an oversized result.
- Errors/logs use stable reason codes and relative paths only. Structured logs introduced here include `case_id`; logging expansion is not required.

## 11. Failure Cases

Typed stable failures or omission reasons must cover:

- missing/malformed/non-reproduced baseline, abnormal evidence, or materially truncated evidence without a reliable category;
- preparation case/revision/fingerprint mismatch or changed prepared bytes;
- unloadable case or malformed/unsafe visible/evaluator paths;
- no identifiable failing visible test;
- conflicting category signals or unknown pytest failure;
- absolute/host/traversal/malformed/duplicate/out-of-repository traceback paths;
- link/reparse/special/evaluator/protected/generated/binary/non-UTF-8/secret/unrelated selected files;
- missing/replaced/mutating/unreadable source, insufficient budget, or AST parse failure;
- ambiguous definitions/import cycles;
- escaping or oversized instruction discovery;
- duplicate items by path case/separator;
- invalid limit, mandatory overflow, or final size beyond budget.

Unknown evidence maps to `unsupported_or_ambiguous`; it is never guessed from benchmark taxonomy. Identity, path, fingerprint, evaluator-boundary, and secret-filter uncertainty fails closed. Safe optional items may be omitted with deterministic metadata.

## 12. Acceptance Criteria

1. Reproduced evidence yields one existing `FailureCategory` and non-empty evidence-derived summary; benchmark taxonomy/reference answers are not consulted.
2. Explicit precedence recognizes syntax, import/dependency, assertion, exception behavior, type, timeout, and environment evidence; conflict/unknown maps to `unsupported_or_ambiguous`.
3. Non-reproduced, infrastructure, malformed, or mismatched inputs cannot reach context selection.
4. The strict typed package is deterministically ordered, contains relative POSIX paths only, and records limit, actual UTF-8 bytes, and omissions.
5. It contains issue, classification, protected policy, bounded trace, identified visible-test context, and available relevant source/definitions/imports/types/instructions without unrelated content.
6. Hidden tests/reference patches are excluded before reads and cannot affect classification, ranking, output, byte counts, summaries, or content-revealing metadata.
7. Generated/cache artifacts, binary/non-UTF-8 files, recognized secrets, host paths, and unrelated files are absent.
8. The limit is never exceeded; ordering/omissions are stable across runs and Windows/Linux path forms.
9. Paths remain within the exact prepared snapshot; traversal, aliases, links/reparse points, replacement, and fingerprint mismatch fail closed.
10. Host selection uses text/static AST inspection only and never imports, executes, compiles, or invokes repository code or shell.
11. Results can populate `LocalRepairCaseState.failure_analysis` and advance status to `analysis_complete` through a typed boundary without unrelated mutation.
12. Tests cover execution-plan requirements: classification correctness, hidden/reference/unrelated exclusion, size enforcement, and path safety.
13. Existing tests plus format, lint, strict typing, full pytest, canonical script, and diff checks pass.
14. No Task 0.1.6+ behavior, dependency, CI permission change, runtime, commit, or push is introduced.

## 15. Definition of Done

- All in-scope behavior/failures use typed deterministic boundaries with acceptance evidence.
- Reproduced evidence uses the existing enum without benchmark answers; ambiguity fails safely.
- The bounded immutable package includes required relevant evidence/static code and excludes evaluator-only, unrelated, generated, binary, secret, and unsafe content.
- Selection revalidates identity/containment, never executes repository code, and never exceeds its UTF-8 budget.
- Section 13 gates pass in Python 3.14; existing Docker integration/security tests pass or locally skip only under established policy.
- README/progress are updated during implementation; governing documents/spec stay unchanged.

## Assumptions Requiring Human Review

1. **Context budget:** approve 32,768 UTF-8 bytes for all downstream-visible fields combined, with injected smaller test limits. The plan requires a bound but specifies no number/tokenizer.
2. **Failure parsing:** approve deterministic pytest/Python text recognition rather than changing Task 0.1.4 to emit machine-readable reports. Unknown, conflicting, or materially truncated evidence maps to `unsupported_or_ambiguous`.
3. **Failing-test selection:** approve evidence-matched declared visible tests, falling back to the sole declared test for current fixtures. Multiple declarations without reliable match fail as ambiguous rather than including all.
4. **Instruction discovery:** approve repository-root `AGENTS.md` and `README.md`, plus nearer `AGENTS.md` along a validated selected path, labeled untrusted. TraceFix's host-root `AGENTS.md` remains governing policy and is not fixture context.
5. **Protected paths:** approve an immutable typed policy containing architecture defaults (`.github/workflows/`, `infra/`, `terraform/`, `deployment/`, `authentication/`, `authorization/`, `security/`, `secrets/`, `migrations/`, and dependency lock files). Enforcement stays in Task 0.1.7.
6. **Secret/generated exclusions:** approve conservative built-in path/name and high-confidence content rules (for example private-key blocks and credential assignments), failing closed for selected candidates. Comprehensive scanning/policy remains deferred.
7. **Snapshot integrity:** approve recomputing the existing versioned SHA-256 fingerprint immediately before selection. This only reads bytes; it does not execute fixture code or change workspace ownership.
