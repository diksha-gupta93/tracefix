# Task 0.1.10a — Graph Routing and CLI Wiring

## 1. Goal

Implement the v0.1 single-attempt LangGraph workflow that composes the existing repository
preparation, baseline, classification, context selection, repair planning, patch generation, patch
policy, static validation, sandbox verification, and candidate evaluation boundaries. Add the
installed command `tracefix repair <case_id>`, deterministic terminal routing, a safe JSON run
artifact, a concise human-readable summary, and stable meaningful process exit codes.

This task is orchestration only. It must reuse the typed behavior implemented by Tasks 0.1.1
through 0.1.9, preserve their trust boundaries, and stop after one repair attempt. It must not add
the deterministic production fake provider, a live provider, benchmark aggregation, persistence,
retries, API ingress, or any later-version behavior.

## 2. Context

Tasks 0.1.1 through 0.1.9 already provide the independently tested v0.1 operations and typed
results:

- `RepositoryPreparer` materializes a trusted failing benchmark snapshot in a caller-owned
  workspace and records its fingerprint.
- `BaselineExecutor` executes only the manifest-declared visible test paths in the hardened pytest
  sandbox and distinguishes reproduced failure, non-reproducible baseline, and infrastructure
  diagnostic.
- `classify_failure`, `ContextSelector`, and `apply_failure_analysis` produce deterministic
  classification and bounded model-safe context.
- `plan_repair`, `generate_patch`, `record_repair_plan`, and `record_patch_proposal` use an injected
  `ModelProvider`, strict model configuration, a single attempt, and typed model diagnostics.
- `validate_patch_policy` evaluates the inert proposal before it can be applied or executed.
- `StaticValidationService` applies an approved proposal only to a fresh candidate copy and
  distinguishes candidate findings from infrastructure diagnostics.
- `VerificationService` runs targeted, complete visible, and hidden tests in fixed order inside
  fresh hardened containers, short-circuits deterministically, and returns safe typed evidence.
- `evaluate_candidate` produces deterministic functional, patch-size, duration, and optional
  model-usage metrics without external access.

There is currently no graph, routing contract, artifact schema/writer, CLI module, console-script
entry point, production fake provider, or live-provider adapter. `LocalRepairCaseState` represents
the Task 0.1.1 through Task 0.1.6 state transitions but does not contain the newer policy, static,
verification, evaluation, routing, workspace-lifecycle, or artifact fields. This task must not
force those newer contracts into legacy list fields with incompatible types; it must introduce a
strict orchestration state that contains the existing typed values.

The architecture defines eleven conceptual workflow nodes. In v0.1, Node 11 produces a terminal
local outcome rather than retrying, persisting, awaiting human approval, or publishing to GitHub.
The execution plan requires these terminal outcomes:

```text
success
candidate_failure
policy_violation
static_check_failure
baseline_not_reproducible
infrastructure_failure
malformed_model_output
```

The repository has a typed model-provider protocol but deliberately has no concrete provider yet.
Task 0.1.10b owns the deterministic fake provider and ordinary-CI end-to-end cases; Task 0.1.11a
owns live-provider benchmark execution. Task 0.1.10a must therefore make workflow construction and
CLI application composition injectable, use test-only stubs for branch tests, and fail safely when
an installed CLI invocation requests a provider that is not yet available.

## 3. In Scope

- Add one strict typed orchestration state for the complete v0.1 run. It must contain, as separate
  typed fields where applicable:
  - immutable run identity and timestamps;
  - `case_id`, attempt number, and the fixed maximum of one attempt;
  - trusted case/revision metadata needed for orchestration;
  - the existing `LocalRepairCaseState` while its legacy transitions apply;
  - preparation, baseline, classification, context, plan, proposal, policy, static-validation,
    verification, and candidate-evaluation values;
  - optional validated model-usage evidence supplied by the application boundary;
  - the terminal route and safe terminal diagnostic; and
  - graph-owned workspace references used only during the run and never serialized into the
    artifact.
- Add a typed LangGraph state transport. If LangGraph requires mapping-shaped updates, use an
  explicit `TypedDict` or equivalent typed schema and validate node input/output through the strict
  orchestration model. Do not pass implicit untyped dictionaries or use `Any`.
- Build and compile one synchronous `StateGraph` with explicit named nodes for:
  1. prepare repository;
  2. run baseline;
  3. classify failure;
  4. select relevant context;
  5. plan repair;
  6. generate patch;
  7. validate patch policy;
  8. run static checks;
  9. verify in sandbox;
  10. evaluate candidate; and
  11. route result.
- Use explicit conditional graph edges. The normal success path must follow the node order above.
  A terminal failure must go directly to Node 11 and must not execute later repair nodes.
- Preserve `max_attempts=1`. Exactly one planning/generation attempt may be recorded, and no graph
  edge may loop back to planning or generation.
- Add a typed dependency bundle or protocols for all external/stateful boundaries used by graph
  nodes, including trusted case loading, model access, Docker-backed execution services,
  filesystem/workspace lifecycle, time/identifier generation, artifact output, and console output.
  Tests must be able to inject deterministic local stubs without monkeypatching global state.
- Construct patch policy from the architecture default protected-path policy and the trusted
  manifest's forbidden changed files. Keep the existing fixed file/line limits and empty dependency
  allowlist; do not invent a CLI override.
- Revalidate the case ID and all typed handoffs at graph/application boundaries. The proposal passed
  to policy, static validation, verification, and evaluation must be the exact proposal generated
  for the active run.
- Add a strict frozen terminal route contract with exactly the seven outcomes listed in Section 2.
  It must include a safe constant diagnostic for every non-success outcome and reject inconsistent
  outcome/evidence combinations.
- Apply the following routing table:

  | Evidence | Terminal outcome |
  | --- | --- |
  | Candidate evaluation is `passed`, verification is `passed`, and every prerequisite passed | `success` |
  | Verification is `candidate_failed` and evaluation is `failed` | `candidate_failure` |
  | Patch-policy result is valid and rejected | `policy_violation` |
  | Static validation is `candidate_failed` | `static_check_failure` |
  | Baseline outcome is `baseline_not_reproducible` | `baseline_not_reproducible` |
  | Preparation, classification, context, filesystem, Docker, sandbox, cleanup, provider, configuration, typed-boundary, or unexpected orchestration failure | `infrastructure_failure` |
  | Planning/generation reports oversized, malformed structured output or an invalid patch envelope | `malformed_model_output` |

- Treat `UNSUITABLE_AUTONOMOUS_REPAIR` as `candidate_failure` for this single-attempt local workflow.
  Treat provider exceptions and missing/invalid/unsupported provider configuration as
  `infrastructure_failure`. Do not expose exception text.
- Run candidate evaluation after every well-formed verification result, including candidate failure
  and infrastructure diagnostic, so its `failed`/`not_evaluated` status is preserved. A failure to
  evaluate otherwise valid typed verification evidence routes to `infrastructure_failure`.
- Add a strict frozen JSON artifact schema. The artifact must include only safe deterministic
  projections of available evidence:
  - integer artifact schema version;
  - run ID, case ID, outcome, and matching exit code;
  - UTC started/completed timestamps;
  - attempt number and `max_attempts=1`;
  - nullable provider name, model name, and prompt version;
  - baseline outcome, safe diagnostic code, completion/exit/truncation/duration metadata, when
    available;
  - nullable failure category;
  - policy approval and safe violation code/relative-path/line metadata, when available;
  - static outcome and safe ordered check metadata, when available;
  - the complete existing safe verification result, when available;
  - the complete existing candidate evaluation result, when available; and
  - one terminal diagnostic code and TraceFix-owned constant message for non-success outcomes.
- The artifact must not contain the proposal diff or prose, source/context content, model prompt or
  raw response, baseline stdout/stderr, raw tool/test/Docker output, hidden-test names/content,
  reference-patch material, exception text, environment values, credentials, secrets, or absolute
  host/container/workspace paths.
- Write artifacts as deterministic UTF-8 JSON with sorted keys, stable indentation, a trailing LF,
  and Pydantic JSON-mode serialization. Do not use `default=str` or lossy ad hoc conversion.
- Add a typed artifact writer that writes atomically and fails closed. By default, one run artifact
  is created beneath `.tracefix/artifacts/` relative to the invocation working directory, named
  `<case_id>-<run_id>.json`. Validate the case ID/run ID, reject aliases and non-directory/special
  output components, use a private same-directory temporary file with exclusive creation, flush
  before atomic replacement, never follow a pre-existing destination, and remove temporary output
  after failure. A destination collision or uncertain write is an infrastructure failure.
- Add `.tracefix/` to `.gitignore`; run artifacts are local generated data and must not be committed
  accidentally.
- Add a graph-owned run workspace lifecycle using one freshly created private temporary root with
  separate non-overlapping preparation, candidate, and verification directories. The application
  owns the complete root and removes it after graph completion on success and every failure path.
  Candidate and prepared trees remain available until routing and artifact projection are complete.
  A cleanup failure changes any otherwise successful/non-infrastructure terminal result to
  `infrastructure_failure` and must be represented safely in the artifact if the artifact writer
  remains usable.
- Add the console-script entry point `tracefix = "app.cli:main"` and implement exactly the required
  public command shape:

  ```text
  tracefix repair <case_id>
  ```

- Use the standard library `argparse`; do not add a CLI-framework dependency. `--help` is allowed as
  normal `argparse` behavior. No additional user-facing repair options are required in this task.
- Validate `<case_id>` before creating a workspace, invoking Docker, loading model configuration,
  or writing an artifact. Syntactically valid but unknown cases are also CLI input errors detected
  before graph invocation.
- Resolve model configuration only through the existing `load_model_configuration` contract and
  resolve a model provider through an injected typed provider factory/registry. The default registry
  is empty in this task. A known case with valid provider-shaped configuration but no registered
  implementation must produce an `infrastructure_failure` run artifact rather than importing a
  provider dynamically or making a network request.
- Print exactly one concise final summary to stdout for a completed run. It must contain the case ID,
  terminal outcome, safe constant summary, exit code, and relative artifact path. CLI usage/unknown-
  case errors go to stderr through normal command-error handling and must not print a traceback.
- Use stable process exit codes:

  | Exit code | Meaning |
  | ---: | --- |
  | `0` | `success` |
  | `1` | `candidate_failure` |
  | `2` | CLI syntax/input error, including unknown case |
  | `3` | `policy_violation` |
  | `4` | `static_check_failure` |
  | `5` | `baseline_not_reproducible` |
  | `6` | `infrastructure_failure` or artifact/workspace cleanup failure |
  | `7` | `malformed_model_output` |

- Return the mapped terminal exit code only after workspace cleanup and artifact writing succeed.
  If artifact writing fails, report a safe message to stderr and return `6`; never claim that an
  artifact exists. Preserve `KeyboardInterrupt` semantics as exit `130` without converting it into
  an ordinary repair outcome, while still attempting workspace and temporary-artifact cleanup.
- Add focused unit and integration tests required by Sections 12 and 13.

## 10. Security Considerations

- Every candidate-controlled action remains inside the existing hardened Docker boundaries. Graph
  orchestration must never import, compile, execute, test, or otherwise evaluate candidate code on
  the host.
- Preserve non-root containers, disabled network, read-only root filesystems, explicit writable
  temporary mounts, CPU/memory/PID/time/output limits, dropped capabilities,
  `no-new-privileges`, required seccomp, fixed environment, unique container identities, bounded
  evidence, and unconditional container/bundle cleanup. Never use `seccomp=unconfined`.
- Never mount or expose the Docker socket, application/model/GitHub credentials, proxy values,
  developer home, project root, benchmark root, evaluator root, reference patch, or arbitrary
  caller path to execution containers.
- Treat case IDs, environment configuration, model output, diffs, repository bytes, typed objects,
  Docker results, filesystem state, clocks/identifiers, artifact destinations, and injected adapter
  responses as untrusted. Revalidate rather than trusting construction, subclassing, mutation, or
  graph transport.
- The graph must fail closed. A missing prerequisite, impossible state combination, duplicate node
  execution, stale/mismatched case or proposal, malformed result, unknown route, or unexpected
  exception can never be interpreted as success.
- Policy rejection occurs before patch application. Static failure occurs before candidate tests.
  Baseline non-reproduction occurs before model invocation. No later node may run after a terminal
  route has been selected.
- Model prompts and responses remain behind the existing typed provider boundary. Do not add dynamic
  provider imports, subprocess providers, network fallback, telemetry, prompt logging, response
  logging, or credential discovery.
- Artifacts and summaries are disclosure boundaries. They must contain only the allowlisted safe
  projection in Section 3. In particular, do not serialize a Pydantic dump of the full graph state
  or `LocalRepairCaseState`, because baseline evidence and graph workspaces can contain raw output
  or host paths.
- Artifact paths must be derived only from the validated case ID and generated/injected validated
  run ID. Reject traversal, separators, drive/root components, NULs, case-fold collisions,
  symlinks/junctions/reparse points, special files, and pre-existing destination files.
- Structured JSON logs remain governed by `AGENTS.md`, but this task must not add a new logging
  framework. If existing/new log events are necessary, they must include `case_id` and may contain
  only the same safe constant metadata permitted in artifacts.
- Workspace cleanup is security-sensitive. Remove only the exact graph-owned temporary root whose
  identity was recorded at creation. Never recursively delete the invocation directory, project
  root, home directory, benchmark tree, an unresolved/aliased path, or an injected arbitrary path.
- `KeyboardInterrupt` and `SystemExit` must trigger best-effort cleanup and then propagate according
  to CLI process-control semantics; they must not be disguised as repair or infrastructure results.

## 11. Failure Cases

The implementation must fail closed and return either a valid terminal artifact or a safe CLI input/
publication error for at least:

- missing, extra, malformed, traversal-shaped, absolute, drive-qualified, overlong, or NUL-containing
  CLI case ID;
- syntactically valid but unknown case ID;
- wrong runtime type, subclass, extra field, mutated Pydantic object, invalid typed graph update, or
  inconsistent state at any node boundary;
- graph compilation failure, missing/duplicate node, unexpected edge, retry cycle, repeated attempt,
  terminal node followed by later execution, or graph completion without exactly one route;
- trusted case load failure, case/revision mismatch, preparation failure, unsafe workspace,
  fingerprint mismatch, source/candidate mutation, cleanup failure, or collision;
- baseline not reproduced, malformed baseline result, sandbox timeout/OOM/validation/execution/
  cleanup failure, or invalid visible-test declaration;
- classification or context failure, unsafe evidence, oversized/invalid context, case mismatch, or
  invalid legacy state transition;
- missing/invalid/unsupported model configuration, no registered provider, provider exception,
  oversized response, malformed structured response, invalid patch envelope, unsuitable autonomous
  repair, or mismatched plan/proposal/state;
- malformed policy input, deterministic policy rejection, inconsistent approval, proposal/result
  pairing mismatch, or attempted policy bypass;
- static candidate failure, static infrastructure diagnostic, missing passing candidate, malformed
  check topology, or proposal/static-candidate mismatch;
- targeted/visible/hidden candidate failure, verification infrastructure diagnostic, malformed
  stage topology, hidden-bundle/integrity/cleanup failure, or verification of a non-passing static
  result;
- malformed proposal/verification/usage evidence supplied to evaluation, impossible evaluation
  status, non-finite or invalid metrics, or evaluation/result mismatch;
- route/evidence disagreement, unsupported terminal outcome, wrong exit-code mapping, missing
  non-success diagnostic, or a success diagnostic where none is allowed;
- artifact schema validation failure, unsafe field entering the projection, nondeterministic JSON,
  invalid filename, output-root alias, destination collision, partial write, flush/close/replace
  error, or temporary-file cleanup failure;
- stdout/stderr writer failure, non-UTF-8 host locale, invocation from a different current directory,
  or platform-specific path/newline behavior; and
- `KeyboardInterrupt` or `SystemExit` during any node, cleanup, or artifact step.

Unknown/invalid case IDs are command-input errors: return exit `2`, print no traceback, create no
workspace, invoke no model/Docker boundary, and write no run artifact. For a known case, every graph
terminal branch attempts workspace cleanup and artifact creation. If cleanup or artifact publication
fails, exit `6`; an incomplete artifact must never be presented as valid.

## 12. Acceptance Criteria

1. One compiled synchronous LangGraph contains exactly the eleven named v0.1 nodes and the explicit
   conditional edges described in Section 3. The normal path runs each node once in order and has
   no repair or infrastructure retry edge.
2. The graph uses one strict orchestration state and typed partial updates. Every node revalidates
   its input/prerequisites and output; no `Any` or implicit untyped dictionary crosses a module
   boundary.
3. Existing typed services are composed rather than reimplemented. The exact generated proposal is
   paired with policy, static validation, verification, and evaluation, and all existing sandbox,
   integrity, evidence, and hidden-test boundaries remain unchanged.
4. Baseline non-reproduction bypasses all model and candidate nodes. Policy rejection bypasses
   static/sandbox/evaluation. Static candidate failure bypasses verification/evaluation.
   Well-formed verification pass/failure/infrastructure evidence proceeds through candidate
   evaluation before routing.
5. Exactly the seven terminal outcomes exist and every evidence branch maps according to the fixed
   routing table. Inconsistent/malformed evidence maps to `infrastructure_failure`, never success.
6. v0.1 records at most one repair attempt. The graph cannot loop, and `attempt_number` never exceeds
   one.
7. A strict versioned artifact is produced for every known-case terminal run. It contains the safe
   allowlisted projection, matches the route and exit code, round-trips deterministically, and
   contains no raw output/content, proposal text/diff, hidden/reference material, exception text,
   secrets, environment data, or absolute path.
8. Artifact publication is atomic and collision-safe beneath `.tracefix/artifacts/`; partial files
   are cleaned after failure, generated artifacts are Git-ignored, and the CLI never claims a
   missing artifact exists.
9. One private graph-owned workspace root contains separate preparation, candidate, and verification
   areas, stays alive through route/artifact projection, and is removed after success and every
   terminal failure. Cleanup uncertainty is visible as infrastructure failure.
10. Editable installation provides `tracefix repair <case_id>`. The command validates arguments and
    unknown cases before side effects, prints one safe summary for completed runs, prints no
    traceback for expected errors, and returns exactly the exit codes in Section 3.
11. The default Task 0.1.10a CLI performs no model network call and dynamically imports no provider.
    Absence of a registered implementation produces a safe `infrastructure_failure` artifact for a
    known case; injected test providers exercise later graph branches.
12. Unit tests independently cover every node transition, every conditional edge, all seven routes,
    state/result invariants, all exit codes, argument validation, unknown case, artifact projection/
    writing, and cleanup paths.
13. Integration tests compile and invoke the real LangGraph with injected deterministic stubs to
    demonstrate success and each terminal branch, exact node order/short-circuiting, artifact
    creation, CLI summary/exit code, and no retry. This is orchestration integration, not the Task
    0.1.10b all-fixture fake-model test.
14. Existing preparation, benchmark isolation, model boundary, policy, static validation,
    verification, evaluation, sandbox, and security tests remain unchanged and passing. Both fixed
    Docker image contracts remain compatible.
15. Formatting, linting, strict typing, dependency integrity, focused tests, applicable Docker
    integration tests, the full suite, canonical validation, installed-command smoke test, and diff
    checks pass under the existing Python 3.14 environment.
16. README and progress documentation are updated during implementation; governing documents and
    the approved specification remain unchanged.
17. No fake/live provider, all-five-case end-to-end CI, benchmark command/report, retry,
    persistence/checkpoint, API, queue, GitHub, observability, unrelated dependency, alternate
    runtime, commit, or push is introduced.

## 15. Definition of Done

- The real LangGraph is compiled with exactly the eleven v0.1 nodes, explicit typed conditional
  routing, deterministic short-circuiting, and no loop or retry.
- One strict orchestration state safely carries the existing typed contracts without weakening or
  duplicating their behavior and without abusing legacy result fields.
- Every supported execution-plan outcome is represented by one strict terminal route with a fixed
  safe diagnostic and stable exit code; malformed or inconsistent evidence cannot produce success.
- `tracefix repair <case_id>` is installed, validates input before side effects, invokes the graph
  through injected typed composition, prints one safe summary, writes one safe atomic artifact for
  known-case terminal runs, and returns the documented exit code.
- The artifact is deterministic, versioned, schema-validated, and limited to safe structured
  metadata. It contains no raw untrusted content, hidden/reference material, secret, exception text,
  environment value, proposal diff, or absolute path.
- Graph-owned preparation/candidate/verification workspaces survive through routing/artifact
  projection and are removed on success, every terminal branch, and interruption. Cleanup
  uncertainty becomes infrastructure failure and cannot be hidden.
- The implementation adds only the bounded LangGraph runtime dependency and standard-library CLI/
  artifact behavior. No concrete model provider is added; an unavailable provider fails safely.
- Focused unit tests cover every schema invariant, node/edge, route, exit code, CLI branch, artifact
  path/projection/write branch, and cleanup branch. Compiled-graph integration tests cover success
  and all six non-success routes without implementing Task 0.1.10b.
- Existing sandbox, benchmark-isolation, planning, policy, static, verification, evaluation, and
  security contracts remain passing and both Docker image contracts remain unchanged.
- All Section 13 gates pass in the existing Python 3.14 environment. Ordinary CI requires no
  secrets, provider network access, database, queue, or GitHub write permission.
- README, `.gitignore`, and progress documentation are updated during implementation; governing
  documents and the approved specification remain unchanged.
- No adjacent/future behavior, unrelated abstraction/dependency, alternative runtime, test
  weakening, commit, or push is included.
- The implementation completion report lists files changed, commands executed, test results,
  acceptance-criteria evidence, architecture decisions, security controls, assumptions, and
  remaining risks/deferred work.

## Assumptions Requiring Human Review

1. **Provider availability boundary:** approve an injectable provider factory/registry whose
   production registry is empty in 0.1.10a. A known-case installed CLI run without a registered
   provider writes an `infrastructure_failure` artifact. Task 0.1.10b supplies the first production
   provider rather than this task silently implementing one.
2. **Orchestration state:** approve a new strict graph-state envelope that contains the existing
   `LocalRepairCaseState` and newer typed results. It does not coerce modern verification/evaluation
   contracts into the legacy `list[TestResult]`/`list[EvaluationResult]` fields.
3. **Model-diagnostic routing:** approve routing malformed/oversized/invalid-envelope output to
   `malformed_model_output`, provider/configuration failures to `infrastructure_failure`, and
   `UNSUITABLE_AUTONOMOUS_REPAIR` to `candidate_failure`. The execution plan names terminal outcomes
   but does not map every Task 0.1.6 diagnostic code.
4. **Unknown-case semantics:** approve treating a syntactically valid but absent case as CLI input
   error exit `2`, before graph/workspace/model/Docker/artifact side effects. The plan requires an
   unknown-case test but does not assign it one of the seven run outcomes.
5. **Exit-code contract:** approve the exact `0`–`7` mapping in Section 3, including shared exit `6`
   for infrastructure, cleanup, and artifact-publication failure and conventional exit `130` for
   `KeyboardInterrupt`.
6. **Artifact location and disclosure:** approve `.tracefix/artifacts/<case_id>-<run_id>.json`
   relative to the invocation directory and the metadata-only projection. In particular, the
   proposal prose/diff is intentionally excluded even on success; later human-review/publication
   tasks may define a separate patch presentation contract.
7. **Artifact lifecycle:** approve no artifact for CLI syntax/unknown-case errors and one attempted
   artifact for every known-case terminal graph run. If publication fails, the command returns `6`
   and reports that no valid artifact was produced.
8. **Workspace cleanup ownership:** approve one application-owned private temporary root with
   separate preparation, candidate, and verification areas, removed only after route/artifact
   projection. This discharges the caller-owned cleanup deferred by Tasks 0.1.8 and 0.1.9.
9. **Cleanup precedence:** approve changing any otherwise successful or product-failure outcome to
   `infrastructure_failure` when final workspace cleanup cannot be proven. The artifact records the
   cleanup diagnostic if safe publication is still possible.
10. **LangGraph dependency:** approve `langgraph>=1.2,<1.3` as the sole new runtime dependency,
    subject to an implementation-time import/compile verification on the existing CPython 3.14
    interpreter. No LangChain package is imported directly and no checkpointer is configured.
11. **v0.1 checkpoint behavior:** approve an in-memory, non-resumable compiled graph with no
    checkpointer. Persistent checkpoints and restart recovery remain v0.2 work.
12. **CI split:** approve compiled-graph and CLI integration with injected test stubs in 0.1.10a,
    while deferring all-five-fixture execution through the installed CLI and deterministic
    production fake provider to 0.1.10b as the execution plan specifies.
